# Live VST lane (Python/value API v1, additive native extension 3)

Use `RealtimeLane` on the worker's existing plugin UI thread. The plugin must already be open at the selected rate and at least the selected maximum block. The constructor loads the trusted configured host/bridge libraries, not a driver. `open_device` initiates the actual owned host; only `status().phase == 'ready'` reports a matched, started stream with observed callback frames. `realtime_ready` is temporarily false during an exclusive control grant. Device and bridge each keep their original retirement responsibilities; neither timer polling nor a park acknowledgement acts as release.

## Route values

The available owned host can open ASIO and WASAPI shared and uses an **exact, unique name** within the chosen host API. Supply `native_selector: {"exact_device": "..."}` from the selected existing catalog row's `name`, retaining its `id` as `device_id`. Only supply a selector where the catalog/native name join is unambiguous; do not derive a driver name from an endpoint ID. The existing host rejects ambiguous native names, and the facade checks the opened API and name. The host cannot independently return a WASAPI endpoint GUID to prove a cross-catalog join. It cannot select arbitrary channel indices; only `[0, 1]` is accepted. RAW, auto, compat, alternate pairs and unmatched routes are rejected, not substituted. No audio_core changes are needed for these supported routes. Device metadata is null until observed, and `buffer_frames` is the observed callback quantum, not a promise that it never varies. Output latency is PortAudio's estimate converted to samples when available, not measured audition latency. `underruns` counts reported output-underflow callbacks. Render position is not a DAC position.

## Values and acknowledgements

- `publish` copies/validates/indexes the prepared value on worker control. The product GUI must not perform that work or wait for it. A reverse triple mailbox transfers only the newest pending immutable timeline at a block boundary. Old and coalesced storage is destroyed by control. A coalesced publication has an explicit stale outcome. Installed and submitted stamps are separate; in particular an earlier epoch in `render_epoch` does not mean the new epoch has applied.
- Play requires a sequence and waits natively for that exact stamp; an overtaken sequence has a stale receipt. Initial Play or audition may establish the first epoch before its timeline arrives. Changing epoch requires a new publication, stops the old source and clears old audition voices. Within an epoch an edit does not stop/seek the stream; shortening past the cursor stops at the new end and a no-longer-valid loop is disabled. Newer transport intents, or following pause/seek/stop, supersede a deferred Play. Already-ready commands are evaluated FIFO.
- B is the sole receipt broker. Call `status()` between finite dispatcher turns, merge receipts by `command_id`, and keep that broker independent of external status pollers. The facade drains the native ring on control turns and reports a non-destructive journal. The journal can recycle only entries already handed to B by `status()`. If it is full of unreported outcomes, or native credits are full, the new submission returns `accepted:false, reason:'busy'`; no accepted command is overwritten. B must retry busy work in order (especially audition off/clear and transport), without blocking Qt. There is reserved native credit for release and transport under audition-on/publish pressure. Unknown-token off is an acknowledged no-op. Receipts are node/command outcomes, not proof of presentation at the DAC.
- `begin_control` returns `{'ticket': ...}`. Only `control_ready(ticket)` for the same ticket permits exclusive state/offline processing. Poll asynchronously and do not nest the event loop during the exclusive operation. `end_control` resumes the prior transport intent, and the next callback chases the current authored state. Park releases outstanding notes/pedals and cancels previously sounding audition gestures; newly queued gestures still apply in order. A device fault can prevent a grant from arriving. Fail the deferred operation rather than fabricate a grant.
- `close_device` requests owned-host retirement immediately, with no dependency on more callbacks. Continue polling `close_ready` even after an error. Plugin unloading requires host release, host destroy, and native bridge destroy. Once retired, the facade rearms a plugin that was used by DSP through its UI-thread VST lifecycle. This preserves the open instance/editor where supported; `plugin_reopen_required` reports refusal. An unresolved driver failure keeps the resources owned. Do not close the Plugin or drop the lane early.

## Rendering and limits

Tempo spans are piecewise constant at the supplied anchors. Use authoritative quarter-note beat values and include boundaries at meter and non-regular bar origins, including pickups. The callback splits at those boundaries and advances within each span; it does not derive elapsed project beat from the current BPM. Adjacent beat anchors are checked within sample quantization. The value schema cannot encode continuous ramps: C must reject a nonrepresentable authoritative curve, including in a final span where continuity checks alone cannot reveal it. Clock evaluation does not certify arbitrary VST use of ProcessContext.

MIDI is stable at equal offsets at the native dispatch boundary. VST separates note events from mapped parameter queues, so the plugin can choose its ordering across those two streams. The host uses only IMidiMapping. Program Change and system messages are not rendered; they do not invalidate an otherwise usable snapshot, and the submission reports how many were unsupported. The document retains these messages. The value schema has no source note IDs, so overlapping note pairs are matched FIFO per channel/key. Native VST note IDs distinguish delivered voices, including audition. Replacement retains IDs for matching crossing keys (onset/channel/pitch/velocity/same-key ordinal), releases removed keys, and chases newly crossing keys. It does not reconstruct prior envelopes or resurrect already released pedal-held notes. Orphan offs are not sent as anonymous note-offs. Actual voice separation depends on the instrument honoring VST IDs. Audition never sends a timeline pedal reset or global all-notes-off, so a mapped sustain pedal may sustain a released audition note until released by the timeline; this is distinct from a stuck token.

Pause/seek/stop/loop discontinuities explicitly release delivered timeline keys and previously set pedals. On playback, authored controller values strictly before the target are restored in source order, followed by exact target events. Channel-mode actions are not replayed as controller state. For other controls with no authored predecessor, there is no generic preset/baseline value to restore. Paused callbacks keep DSP warm and can render auditions and release tails without advancing project time. Exclusive park instead silences DSP. Vendor tails, controller aliases and pedal capabilities must be verified with the selected instrument.

Limits include 1,048,576 events, 262,144 clock boundaries, 4,096 authored events at one sample, 4,016 key-down timeline notes, 128 audition tokens, and 64 process segments per callback. Authored density can split a block at a sample boundary; synthetic transition events have additional native headroom. Unsupported density or a runaway short-loop workload produces explicit rejection or a sticky fault, not silent truncation. The host pool covers every mapped channel/controller queue plus the bounded UI edit queue, and all per-call MIDI points plus their coalesced UI initial values. Driver and vendor CPU costs still require measurement.

## Reviewed output mix, free meter and transport smoothing

ABI 3 mixes `(plugin * midi_gain + PCM * audio_gain + click * click_gain) * master_gain`, with independent mute. The product sends master/MIDI separately, so MIDI 0 does not silence PCM or click. Legacy gain is mutually exclusive with split fields and maps to master only. Initial gains apply before the first callback; mix changes keep the original 5 ms ramps without reopening the device.

Explicit prepared click sample points use the authoritative native pulse map. Ordinary/pickup/short-bar accents follow native measure starts. Free meter uses actual pulse evidence with no fabricated bar accent; no pulse evidence means no click. PCM uses the same render sample and callback; asynchronous cache readiness is distinct from request acceptance. Playback-rate changes and nonzero plugin-latency compensation are not implemented.

At a real transport discontinuity, a finite 5 ms **pre-master pooled-output declick** bridges the previous L/R mixed sample to the current mixed output. It is not a naturally rendered old tail, replayed history, or an extra old timeline. The first output sample preserves the last pooled value; the old contribution reaches zero after 240 samples at 48 kHz, independently of callback block size. There is no steady-state delay, added lock, allocation, or second clock.

Pause/seek/stop/play position and receipt semantics remain immediate. Commands retain FIFO processing. Repeated transitions start from the current interpolated output, not unity. Same-epoch note edits do not arm this transition unless they genuinely stop transport. Natural loop/end boundaries use the same finite bridge; very short loops can remain in transition. Zero-frame callbacks do not advance it. New epochs, fault, park and desired mute clear saved history. Master/mute still apply after the bridge, so stored audio never bypasses them. Pause keeps plugin DSP warm with its existing audition/release tails; this is not a permanent transport mute and not a promise of hardware click elimination.

Repeated transitions while a bridge is active retain its original remaining sample budget (rebase from the current output, do not renew the deadline). This also bounds history after disabling click during a very short loop.

A bus gain/off command retains its existing 5 ms bus ramp. If transport discontinuities overlap that ramp, total disappearance can take up to the bus ramp plus one finite transport bridge (10 ms at 48 kHz), not 5 ms from the mix command.
